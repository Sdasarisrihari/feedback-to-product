## Evidence and AI quality

- Exact quote presence checks do not establish whether a claim is entailed. Case/smart-quote normalization is used; returned accepted excerpts are source text.
- PRD requirements/stories are downgraded when **all** feedback quotes fail; a single accepted quote can leave a compound claim insufficiently supported. Do not interpret the UI's supported label as human quality approval.
- Zod checks types/structure, not meaningful nonempty prose, unique item IDs, minimum story counts or acceptance-criteria observability. Given/When/Then formatting is not a quality test. Free-text scope, risks, dependencies, answer prose and `baselineKnown` can still contain unsupported statements.
- Human editing appends content with no new grounding report; it does not automatically re-verify changed claims. A prior server-checked label does not validate human-added text.
- PRD source snapshots are on the mutable parent document, not each revision. Regeneration can change the sources displayed alongside an older revision. Freeze the exact draft and sources outside this mutable parent for genuine evaluation.
- Saved themes/provenance are owner-controlled persisted data, not cryptographically attested model results. MCP rechecks quotes but does not prove a stored summary was generated by a model or semantically supported.
- Rating-based sentiment, keyword severity, enterprise share and citation-count confidence are proxies, not calibrated sentiment/severity/confidence models. Fixed BM25 baseline only covers its development theme catalogue.
- Untrusted content flags, angle-delimiter escaping and instructions reduce risk but do not prove prompt-injection immunity. XML-like attribute values are not completely escaped. Four injection examples/limited marker checks are not a red-team benchmark.

## Source, ingestion and retrieval limits

- Analysis uses ≤300 records, ≤1,500 characters each. The flag reflects record-count truncation, not every text cut. Server validator permits larger original texts before trimming.
- PRD browser sources truncate feedback at 4,000 characters; saved full-text reconciliation then rejects mismatches for long signed-in sources. Q&A also rejects text above its 4,000-character schema limit. Context-budget rejection is not a missing customer need.
- Document target chunk size is 1,200 characters but a long single paragraph/CSV row can exceed it. No OCR: image-only PDF pages are not readable; mixed text/scanned pages can omit information.
- PDF extraction reads only the first 200 pages, without an explicit page-limit warning. The importer can report success for incomplete extraction. Files over 5 MiB are rejected in document UI; feedback CSV limit is 2 MiB.
- Document reimports create collision-safe new IDs rather than content-idempotent deduplication. Feedback duplicate handling is normalized text, not semantic similarity; some analysis/retrieval paths exclude flagged duplicates while MCP can show them.
- BM25 is lexical; separate per-type scores are merged without calibrated cross-source normalization. No vector database, embeddings or reranker. Search filters affect displayed hits; Ask AI retrieves both feedback/docs regardless of that filter.

## Persistence, identity and operations

- Same-row last-write-wins across tabs/devices; no version-conflict UI or optimistic lock. Simultaneous revision-number collisions can be ignored by insert-only upsert rather than reported.
- Multi-table/batch saves are not transactional. Partial failures can leave some rows applied; retries retain unsaved UI state, not a durable offline journal. Interrupted imports are not proven atomic.
- ID/order-only analysis signature misses same-ID text changes. In-flight runs assign a signature from current records upon completion, not necessarily the original analyzed snapshot. Staleness handling is implemented, but not universal.
- Signed-out storage is local to a browser profile; clearing it erases demo data. Shared browsers may retain previous browser-demo content; fresh visitors start empty, but reopening a used browser does not necessarily show empty.
- First-time opt-in import, signup/email confirmation and hosted Google configuration are only partly/previously tested. Settings presence is not proof hosted auth is correctly configured. Sign-out uses the auth client's default global session behavior; do not disrupt an interview account casually.
- Owner-scoped policies and controlled security tests do not prove live access denial across two populated production owners. That real check remains pending, as do real expired/revoked OAuth credentials and hosted failure recovery.
- MCP database fetches have a 15-second per-fetch deadline, not an entire-operation SLA; larger saved corpora have bounded fetch budgets. Deployment of the latest timeout revision was not verified.
- No app-enforced per-caller inference quotas or total LLM deadline was found. Signed-out inference endpoints can consume model access without a signed-in workspace. Provider rate-limit messages are not app rate limiting.
- No comprehensive penetration test, dependency audit, backup/restore drill, retention/deletion policy validation, sensitive-log audit or production load test was performed. Generic handlers log error objects; do not claim zero sensitive logging universally.

## Evaluation limitations

Synthetic builder/same-system authorship; small datasets; nominal held-out records already exposed; original majority mapping uses gold labels; frozen challenge mapping differs; two repeats are not independent samples. Exact citations, capability proxies, retrieval section counts and semantic pair rates have different units. Semantic-v2 atomic scoring and PRD output assessment are still blocked. No causal productivity lift, revenue, time saving or validated customer outcome is measured.
